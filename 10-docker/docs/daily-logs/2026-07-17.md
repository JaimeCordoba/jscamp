## Notas Clave y Teoría

### 1. Ejecución en Segundo Plano
- **Parámetro `-d` (detach)**: Permite correr un contenedor sin bloquear la terminal. Docker nos devuelve de inmediato el **Container ID** único y el control de la terminal para poder seguir trabajando.
- **Container ID**: Cadena larga que identifica unívocamente a cada contenedor. Se utiliza para consultarle logs, detenerlo, inspeccionarlo o eliminarlo. Se puede abreviar usando sus primeros caracteres en los comandos.

### 2. Monitoreo y Gestión
- **Listado de Contenedores (`docker ps`)**: 
  - `docker ps`: Muestra únicamente los contenedores que están en ejecución.
  - `docker ps -a`: Muestra todos los contenedores en el host, incluyendo los que están detenidos/finalizados.
- **Logs del Contenedor**:
  - `docker logs <container-id>`: Recupera y muestra el historial de salida estándar y error del contenedor en segundo plano.
  - `docker logs -f <container-id>`: Sigue los logs en vivo (follow mode), refrescándose automáticamente con cada nuevo evento.
- **Detener Contenedores**:
  - `docker stop <container-id>`: Envía una señal de parada al contenedor para finalizar su ejecución de forma controlada y segura.

### 3. Estructura de Archivos e Inspección
- **Inspección de Archivos**: Es posible entrar o examinar el sistema de archivos interno de un contenedor para ver su estructura, que cuenta con los directorios clásicos de Linux (como `bin`, `etc`, etc.).
- **Importancia de `WORKDIR`**:
  - Define el directorio de trabajo donde se guardará y ejecutará la aplicación de forma aislada.
  - **Evitar trabajar desde la raíz (`/`)**: Copiar los archivos directamente en la raíz es una mala práctica que puede causar conflictos con directorios del sistema (como `usr`, `var`, `tmp`), dificultar la organización y poner en riesgo la estabilidad del contenedor.

### 4. Variables de Entorno en Docker
- **Inyección de Variables**:
  - **Individuales (`-e`)**: Permite declarar variables en el comando `docker run` (ej. `-e SALUDO="Hola Midus"`).
  - **Desde Archivo (`--env-file`)**: Permite cargar un archivo (como `.env`) con múltiples variables de entorno de golpe, lo cual es ideal para entornos complejos.
- **Ventajas y Buenas Prácticas**:
  - Permite configurar puertos, credenciales, URLs de APIs, etc., sin modificar el código de la aplicación.
  - Permite usar exactamente la misma imagen Docker en múltiples entornos (desarrollo, pruebas, producción), asegurando la portabilidad de las imágenes.

### 5. Limpieza y Mantenimiento de Espacio
- **Uso de Disco**: `docker system df` ofrece un desglose del espacio consumido por imágenes, contenedores, volúmenes y la caché de construcción.
- **Comandos de Limpieza**:
  - `docker system prune`: Elimina de forma segura contenedores detenidos, redes inactivas y caché de build obsoleta.
  - `docker system prune -a`: Limpieza profunda que elimina además todas las imágenes locales que no estén asociadas a un contenedor activo. Debe usarse con precaución ya que obligará a descargar o reconstruir las imágenes la próxima vez que se requieran.

### 6. Optimización con `.dockerignore`
- **Contexto de Construcción (Build Context)**: Al ejecutar `docker build`, Docker envía todos los archivos del directorio de trabajo al daemon de Docker. `.dockerignore` funciona de forma similar a `.gitignore` y permite excluir del contexto aquellos directorios o archivos innecesarios.
- **Beneficios**:
  - Acelera la construcción de imágenes y evita incluir archivos innecesarios del entorno local (como `node_modules`, `.git`, `.vscode`, `*.md` o `.DS_Store`).
- **Problema de Dependencias Cruzadas**: Al compilar dependencias nativas localmente (en macOS o Windows), estas no funcionarán en un contenedor Linux. Al ignorar `node_modules` locales y correr `RUN npm ci` dentro del contenedor se garantiza que los binarios se compilen para el sistema operativo destino correcto.

### 7. Sistema de Capas y Caché de Construcción
- **Concepto de Capas**: Cada instrucción importante (`FROM`, `RUN`, `COPY`, `ADD`) en el `Dockerfile` crea una nueva capa de sólo lectura.
- **Funcionamiento de la Caché**: Docker procesa las capas secuencialmente. Si detecta que el contenido de una capa ha cambiado, invalida esa capa y **todas** las capas posteriores, obligando a rehacer todo el trabajo posterior.
- **Optimización de Builds**:
  - **Práctica Ineficiente**: Copiar todo el código (`COPY . .`) antes de instalar dependencias (`RUN npm install`). Cualquier cambio de código invalida la caché y fuerza la reinstalación de todos los paquetes.
  - **Práctica Eficiente**: Separar la copia de archivos de configuración (`COPY package.json .`) de la copia del código fuente (`COPY . .`):
    ```dockerfile
    COPY package.json .
    RUN npm install
    COPY . .
    ```
    Esto permite que la instalación de dependencias permanezca en caché y las reconstrucciones de código se completen casi de manera instantánea (0 segundos).

### 8. Automatización con `docker init`
- **Comando `docker init`**: Utilidad de automatización integrada en Docker que analiza el proyecto en busca de lenguaje, framework y runtime para guiar al desarrollador en la creación rápida de archivos de configuración.
- **Asistente y Preguntas**: Configura interactivamente la versión de runtime, puerto, comando y gestor de paquetes de manera fácil.
- **Archivos Generados**: Crea un `Dockerfile` optimizado (a veces usando montajes de caché temporales), `.dockerignore` y la base para Docker Compose (`compose.yaml`).

### 9. Publicación de Imágenes en Docker Hub
- **Docker Hub**: Registro público oficial (análogo a GitHub para código) que permite almacenar, versionar y compartir imágenes de Docker de forma gratuita (públicas o privadas).
- **Búsqueda desde Terminal**: El comando `docker search <término>` (ej. `docker search postgres`) permite consultar imágenes directamente en Docker Hub sin usar el navegador. Se recomienda priorizar imágenes oficiales verificadas.
- **Preparación de la Imagen**:
  - **Prefijo de Usuario**: Es necesario añadir el usuario de Docker Hub como prefijo en el nombre de la imagen (ej. `usuario/nombre-imagen`) para evitar conflictos de nombres.
  - **Tags (Etiquetas)**: Se usan para versionar (ej. `:0.0.1`). Si no se especifica, por defecto toma `:latest`.
- **Publicación y Ejecución**:
  - **Subida (`docker push`)**: `docker push usuario/nombre-imagen:tag` sube la imagen a Docker Hub.
  - **Etiquetado (`docker tag`)**: `docker tag imagen-origen imagen-destino` permite crear un alias/etiqueta nueva de una imagen existente (por ejemplo, para renombrarla con el prefijo de usuario) sin reconstruirla.
  - **Descarga y Ejecución**: Cualquier usuario puede descargar y ejecutar la imagen publicada mediante `docker run usuario/nombre-imagen:tag`.

### 10. Construcción Multipaso (Multi-stage Builds)
- **Problema de imágenes tradicionales**: Si copiamos todo el proyecto en una sola etapa, la imagen final incluirá código fuente, dependencias de desarrollo (`devDependencies`) y archivos de compilación innecesarios. Esto genera imágenes muy pesadas, lentas y con mayor superficie de ataque.
- **Concepto Multipaso**: Permite dividir el proceso de construcción en múltiples fases independientes dentro del mismo `Dockerfile`.
- **Estructura típica**:
  - **Fase de Compilación (`builder`)**: Usa una imagen base con todas las herramientas necesarias para compilar el código (ej. `FROM node:alpine AS builder`). Instala dependencias completas, copia el código fuente y ejecuta el script de build (ej. `npm run build` para generar la carpeta `dist`).
  - **Fase de Ejecución (`runner`)**: Inicia desde una imagen base limpia (ej. `FROM node:alpine AS runner`). Copia únicamente el resultado compilado de la etapa anterior usando `COPY --from`:
    ```dockerfile
    COPY --from=builder /app/dist ./dist
    ```
- **Optimización de Entorno**: Es recomendable declarar `ENV NODE_ENV=production` en la etapa de ejecución para indicarle a frameworks y librerías que desactiven herramientas de depuración y optimicen el rendimiento.
- **Beneficios**:
  - Imágenes finales extremadamente ligeras (solo contienen los archivos listos para servir).
  - Mayor seguridad al no exponer código fuente ni herramientas de desarrollo.
  - Despliegues y descargas mucho más rápidos en servidores de producción.

### 11. Persistencia de Datos: Volúmenes y Bind Mounts
- **Naturaleza Efímera**: Los contenedores no guardan estado permanentemente; si un contenedor es destruido, todos los datos generados dentro de él se pierden.
- **Docker Volumes**:
  - **Concepto**: Almacenamiento persistente administrado directamente por Docker.
  - **Uso**: Útil para bases de datos (ej. PostgreSQL) o archivos de usuario. Los datos sobreviven a la eliminación del contenedor y pueden compartirse entre múltiples contenedores.
  - **Comandos**:
    - Crear volumen: `docker volume create <nombre>`
    - Montar volumen: `docker run -v nombre-volumen:/ruta/en/contenedor <imagen>`
    - Eliminar volumen (debe hacerse manualmente): `docker volume rm <nombre>`
- **Bind Mounts**:
  - **Concepto**: Enlaza una carpeta específica de la máquina anfitriona (host) con una carpeta dentro del contenedor.
  - **Uso**: Ideal para desarrollo local. Cualquier cambio en los archivos locales se refleja inmediatamente en el contenedor sin necesidad de reconstruir la imagen.
  - **Uso de `--watch` (Hot Reload)**: Al combinar un Bind Mount de la carpeta del proyecto (ej. `${pwd}:/app`) con herramientas como `node --watch` o `nodemon`, la aplicación se reinicia automáticamente al editar código desde el editor local.
- **Diferencia Clave**:
  - **Docker Volume**: Administrado por el motor de Docker en una zona reservada del disco del host. Portabilidad y rendimiento óptimo.
  - **Bind Mount**: Depende de la estructura de archivos específica del host. Ideal para compartir el código fuente en entornos de desarrollo.

### 12. Ejecución de Modelos de Inteligencia Artificial (Docker Models)
- **Modelos de IA Locales**: Docker incorpora soporte nativo para gestionar y ejecutar modelos de IA de forma local (similar a herramientas como Ollama) sin depender de APIs de pago externas.
- **Flujo de Trabajo**:
  - **Búsqueda**: `docker model search <término>` permite buscar modelos compatibles (ej. `gemma`, `ai/smollm2`).
  - **Descarga**: `docker model pull <modelo>` descarga el modelo al disco local.
  - **Listado y Estado**: `docker model list` muestra los modelos instalados, sus parámetros, cuantización y arquitectura.
  - **Ejecución interactiva**: `docker model run <modelo>` permite chatear directamente en la terminal con el modelo local.
- **API Local Integrada**:
  - Al arrancar un modelo, Docker levanta automáticamente una API HTTP local.
  - **Compatibilidad con OpenAI**: Esta API es compatible con el formato y SDK oficial de OpenAI (`client.chat.completions.create`), lo que permite reutilizar el código de la aplicación y alternar fácilmente entre modelos locales y de producción en la nube (ej. GPT-4) solo modificando el `base_url`.
- **Integración entre Contenedores**:
  - Si una aplicación (ej. una app Flask o Node.js) corre en otro contenedor en el host, puede comunicarse con el servicio de IA local a través de una URL de red interna especial que Docker gestiona de forma transparente.

### 13. Asistente Virtual: Docker AI (Gordon)
- **¿Qué es Docker AI?**: Un asistente de inteligencia artificial integrado directamente en Docker Desktop conocido como Gordon, que actúa como un experto en Docker accesible en todo momento.
- **Acceso a Contexto**: El asistente tiene acceso al estado de tu entorno Docker, incluyendo contenedores, imágenes, Dockerfiles, archivos del proyecto e información del sistema.
- **Interacción por Lenguaje Natural**: Permite realizar consultas (ej. *¿Cuántos contenedores tengo?*, *Explícame este error*) o dar instrucciones directas (ej. *Borra todos los contenedores*, *Crea un Dockerfile para esta aplicación*) en lugar de ejecutar comandos de forma manual.
- **Seguridad y Confirmación**: Como medida de prevención ante errores accidentales, Docker AI siempre solicita confirmación explícita antes de ejecutar cualquier acción destructiva o que modifique de forma crítica el sistema.
- **Casos de Uso Principales**:
  - **Gestionar Contenedores**: Listar, inspeccionar o eliminar contenedores mediante peticiones sencillas.
  - **Generar y Mejorar Dockerfiles**: Crear archivos de configuración para el proyecto o auditar y reescribir Dockerfiles existentes siguiendo buenas prácticas.
  - **Revisión de Seguridad**: Explicar vulnerabilidades detectadas por Docker Scout y sugerir soluciones o mejores opciones de imágenes base.
  - **Resolución de Problemas**: Analizar mensajes de error de la terminal y proponer soluciones basadas en el contexto del entorno.
- **Disponibilidad y Coste**: Está integrado de forma nativa y 100% gratuita dentro de Docker Desktop, sin requerir herramientas o dependencias adicionales.

### 14. Despliegue de Docker en Vercel
- **Despliegues Dockerizados**: Vercel ahora permite desplegar aplicaciones empaquetadas en contenedores Docker (incluso en su plan gratuito), lo que abre la posibilidad de hospedar servicios o APIs en cualquier lenguaje que cuente con un `Dockerfile` compatible.
- **Dockerfile Personalizado (`Dockerfile.vercel`)**: Por defecto, Vercel busca un archivo llamado `Dockerfile.vercel` para detectar el despliegue de contenedores, aunque permite indicar otros nombres durante la construcción.
- **Construcción Multipaso (Multi-stage Builds)**: Es altamente recomendable para compilar la aplicación (por ejemplo en Go o Node) en una primera fase y copiar solo el binario o compilación final limpia a una imagen ligera (como Alpine o scratch) en la fase de ejecución, garantizando imágenes rápidas y seguras.
- **Varios Dockerfiles en un Proyecto**: Se pueden mantener múltiples Dockerfiles para distintos propósitos (ej. `Dockerfile.vercel`, `Dockerfile.server`, `Dockerfile.database`). Se especifica cuál usar al construir indicando el parámetro `-f`.
  - Construir: `docker build -f Dockerfile.vercel -t vercel .`
  - Ejecutar localmente para probar: `docker run --rm -p 8080:80 vercel`
- **Flujo de Trabajo CLI**:
  1. Instalar la CLI globalmente: `npm install -g vercel`.
  2. Iniciar sesión: `vercel login`.
  3. Desplegar: Ejecutar `vercel` en la raíz del proyecto para que la plataforma detecte, compile y despliegue el contenedor.

## Comandos Clave
- `docker run -d <imagen>` - Ejecuta un contenedor en segundo plano y devuelve su ID.
- `docker ps` - Lista los contenedores actualmente activos.
- `docker ps -a` - Lista todos los contenedores (activos y detenidos).
- `docker logs <container-id>` - Muestra el historial de logs de un contenedor.
- `docker logs -f <container-id>` - Sigue la salida de logs de un contenedor en tiempo real.
- `docker stop <container-id>` - Detiene de manera controlada un contenedor activo.
- `docker images` - Lista todas las imágenes de Docker almacenadas localmente.
- `docker run -e CLAVE="valor" <imagen>` - Ejecuta un contenedor inyectándole una variable de entorno.
- `docker run --env-file <archivo> <imagen>` - Ejecuta un contenedor cargando las variables de entorno desde un archivo.
- `docker system df` - Muestra el desglose del uso de espacio en disco de Docker.
- `docker system prune` - Elimina contenedores detenidos, redes sin uso y caché.
- `docker system prune -a` - Realiza una limpieza completa eliminando también todas las imágenes no utilizadas por contenedores activos.
- `docker init` - Inicializa un asistente para generar automáticamente la configuración de Docker en un proyecto.
- `docker search <nombre>` - Busca imágenes en Docker Hub desde la terminal.
- `docker tag <imagen-origen> <imagen-destino>` - Genera una nueva etiqueta o referencia para una imagen existente.
- `docker push <usuario>/<imagen>:<tag>` - Sube una imagen con su etiqueta correspondiente a Docker Hub.
- `docker volume create <nombre>` - Crea un nuevo volumen persistente gestionado por Docker.
- `docker volume rm <nombre>` - Elimina de forma permanente un volumen y todos sus datos.
- `docker run -v <volumen-o-ruta-host>:<ruta-contenedor> <imagen>` - Ejecuta un contenedor montando un volumen o un Bind Mount en la ruta especificada.
- `docker model search <nombre>` - Busca modelos de inteligencia artificial en el catálogo de Docker.
- `docker model pull <modelo>` - Descarga un modelo de IA localmente.
- `docker model list` - Lista los modelos de IA instalados y sus especificaciones.
- `docker model run <modelo>` - Ejecuta un modelo de IA de forma interactiva desde la terminal.
- `npm install -g vercel` - Instala globalmente la interfaz de línea de comandos (CLI) de Vercel.
- `vercel login` - Autentica al usuario en su cuenta de Vercel a través de la terminal.
- `vercel` - Inicia el proceso de compilación y despliegue del proyecto en la plataforma Vercel.
- `docker build -f <archivo> -t <etiqueta> <contexto>` - Construye una imagen especificando explícitamente un archivo de Dockerfile alternativo mediante el parámetro `-f`.
