## Notas Clave y Teoría

### 1. Ejecución en Segundo Plano
- **Parámetro `-d` (detach)**: Permite correr un contenedor sin bloquear la terminal. Docker nos devuelve de inmediato el **Container ID** único y el control de la terminal para poder seguir trabajando.
- **Container ID**: Cadena larga que identifica unívocamente a cada contenedor. Se utiliza para consultarle logs, detenerlo, inspeccionarlo o eliminarlo. Se puede abreviar usando sus primeros caracteres en los comandos.

### 2. Monitoreo y Gestión
- **Listado de Contenedores (`docker ps`)**: 
  - `docker ps`: Muestra únicamente los contenedores que están en ejecución.
  - `docker ps -a`: Muestra todos los contenedores en el host, incluyendo los que están detenidos/finalizados.
- **Logs del Contenedor**:
  - `docker logs <container-id>`: Recupera y muestra el historial de salida estándar y error del contenedor en segundo plano.
  - `docker logs -f <container-id>`: Sigue los logs en vivo (follow mode), refrescándose automáticamente con cada nuevo evento.
- **Detener Contenedores**:
  - `docker stop <container-id>`: Envía una señal de parada al contenedor para finalizar su ejecución de forma controlada y segura.

### 3. Estructura de Archivos e Inspección
- **Inspección de Archivos**: Es posible entrar o examinar el sistema de archivos interno de un contenedor para ver su estructura, que cuenta con los directorios clásicos de Linux (como `bin`, `etc`, etc.).
- **Importancia de `WORKDIR`**:
  - Define el directorio de trabajo donde se guardará y ejecutará la aplicación de forma aislada.
  - **Evitar trabajar desde la raíz (`/`)**: Copiar los archivos directamente en la raíz es una mala práctica que puede causar conflictos con directorios del sistema (como `usr`, `var`, `tmp`), dificultar la organización y poner en riesgo la estabilidad del contenedor.

### 4. Variables de Entorno en Docker
- **Inyección de Variables**:
  - **Individuales (`-e`)**: Permite declarar variables en el comando `docker run` (ej. `-e SALUDO="Hola Midus"`).
  - **Desde Archivo (`--env-file`)**: Permite cargar un archivo (como `.env`) con múltiples variables de entorno de golpe, lo cual es ideal para entornos complejos.
- **Ventajas y Buenas Prácticas**:
  - Permite configurar puertos, credenciales, URLs de APIs, etc., sin modificar el código de la aplicación.
  - Permite usar exactamente la misma imagen Docker en múltiples entornos (desarrollo, pruebas, producción), asegurando la portabilidad de las imágenes.

### 5. Limpieza y Mantenimiento de Espacio
- **Uso de Disco**: `docker system df` ofrece un desglose del espacio consumido por imágenes, contenedores, volúmenes y la caché de construcción.
- **Comandos de Limpieza**:
  - `docker system prune`: Elimina de forma segura contenedores detenidos, redes inactivas y caché de build obsoleta.
  - `docker system prune -a`: Limpieza profunda que elimina además todas las imágenes locales que no estén asociadas a un contenedor activo. Debe usarse con precaución ya que obligará a descargar o reconstruir las imágenes la próxima vez que se requieran.

### 6. Optimización con `.dockerignore`
- **Contexto de Construcción (Build Context)**: Al ejecutar `docker build`, Docker envía todos los archivos del directorio de trabajo al daemon de Docker. `.dockerignore` funciona de forma similar a `.gitignore` y permite excluir del contexto aquellos directorios o archivos innecesarios.
- **Beneficios**:
  - Acelera la construcción de imágenes y evita incluir archivos innecesarios del entorno local (como `node_modules`, `.git`, `.vscode`, `*.md` o `.DS_Store`).
- **Problema de Dependencias Cruzadas**: Al compilar dependencias nativas localmente (en macOS o Windows), estas no funcionarán en un contenedor Linux. Al ignorar `node_modules` locales y correr `RUN npm ci` dentro del contenedor se garantiza que los binarios se compilen para el sistema operativo destino correcto.

### 7. Sistema de Capas y Caché de Construcción
- **Concepto de Capas**: Cada instrucción importante (`FROM`, `RUN`, `COPY`, `ADD`) en el `Dockerfile` crea una nueva capa de sólo lectura.
- **Funcionamiento de la Caché**: Docker procesa las capas secuencialmente. Si detecta que el contenido de una capa ha cambiado, invalida esa capa y **todas** las capas posteriores, obligando a rehacer todo el trabajo posterior.
- **Optimización de Builds**:
  - **Práctica Ineficiente**: Copiar todo el código (`COPY . .`) antes de instalar dependencias (`RUN npm install`). Cualquier cambio de código invalida la caché y fuerza la reinstalación de todos los paquetes.
  - **Práctica Eficiente**: Separar la copia de archivos de configuración (`COPY package.json .`) de la copia del código fuente (`COPY . .`):
    ```dockerfile
    COPY package.json .
    RUN npm install
    COPY . .
    ```
    Esto permite que la instalación de dependencias permanezca en caché y las reconstrucciones de código se completen casi de manera instantánea (0 segundos).

### 8. Automatización con `docker init`
- **Comando `docker init`**: Utilidad de automatización integrada en Docker que analiza el proyecto en busca de lenguaje, framework y runtime para guiar al desarrollador en la creación rápida de archivos de configuración.
- **Asistente y Preguntas**: Configura interactivamente la versión de runtime, puerto, comando y gestor de paquetes de manera fácil.
- **Archivos Generados**: Crea un `Dockerfile` optimizado (a veces usando montajes de caché temporales), `.dockerignore` y la base para Docker Compose (`compose.yaml`).

## Comandos Clave
- `docker run -d <imagen>` - Ejecuta un contenedor en segundo plano y devuelve su ID.
- `docker ps` - Lista los contenedores actualmente activos.
- `docker ps -a` - Lista todos los contenedores (activos y detenidos).
- `docker logs <container-id>` - Muestra el historial de logs de un contenedor.
- `docker logs -f <container-id>` - Sigue la salida de logs de un contenedor en tiempo real.
- `docker stop <container-id>` - Detiene de manera controlada un contenedor activo.
- `docker images` - Lista todas las imágenes de Docker almacenadas localmente.
- `docker run -e CLAVE="valor" <imagen>` - Ejecuta un contenedor inyectándole una variable de entorno.
- `docker run --env-file <archivo> <imagen>` - Ejecuta un contenedor cargando las variables de entorno desde un archivo.
- `docker system df` - Muestra el desglose del uso de espacio en disco de Docker.
- `docker system prune` - Elimina contenedores detenidos, redes sin uso y caché.
- `docker system prune -a` - Realiza una limpieza completa eliminando también todas las imágenes no utilizadas por contenedores activos.
- `docker init` - Inicializa un asistente para generar automáticamente la configuración de Docker en un proyecto.
