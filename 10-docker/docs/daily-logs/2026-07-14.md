## Notas Clave y Teoría
- **Dockerfile**: Un archivo de receta que describe cómo construir una imagen de contenedor (imagen base, archivos a copiar, directorio de trabajo, comando de inicio).
- **Imagen Base**: Toda imagen comienza a partir de otra imagen existente. Alpine Linux es muy popular para Node.js debido a que es extremadamente ligera, segura y eficiente.
- **Imagen vs Contenedor**:
  - *Imagen*: Plantilla inmutable que contiene el código, las dependencias y la configuración de la aplicación. Se asemeja a una **receta**. Se descarga y almacena localmente tras su primer uso para ejecuciones instantáneas posteriores.
  - *Contenedor*: Instancia en ejecución basada en una imagen. Se asemeja al **plato cocinado**. Puede estar corriendo, detenido o ser eliminado.
- **Instalación y Docker Desktop**:
  - **Docker Desktop** (opción recomendada): Instala automáticamente Docker Engine, Docker CLI, Docker Compose y una interfaz gráfica (GUI) de administración.
  - **Sistemas Operativos**: Funciona en macOS, Windows y Linux. En Windows se recomienda usar **WSL (Windows Subsystem for Linux)** para un rendimiento óptimo.
  - **Licencia**: Gratis para uso personal, requiere suscripción de pago para ciertas empresas grandes.
  - **Alternativas**: OrbStack, Podman Desktop, Rancher Desktop, Colima.
- **Máquinas Virtuales vs Contenedores**:
  - **Máquina Virtual (VM)**: Virtualiza todo el hardware e incluye un sistema operativo completo. Es pesada (GBs), lenta en arrancar (segundos/minutos) y consume más CPU/RAM.
  - **Contenedor Docker**: Proceso aislado que comparte el kernel del SO del host. Incluye solo la app y sus dependencias directas. Es ligero (MBs), arranca al instante (milisegundos) y consume mínimos recursos.
  - **Docker Engine**: En macOS y Windows, ejecuta los contenedores sobre una única máquina virtual Linux ligera y optimizada (compartida por todos los contenedores). En Linux, funciona de manera nativa sin máquinas virtuales intermedias, ofreciendo rendimiento nativo.
- **Casos de Uso de Docker**:
  - **Desarrollo Local Limpio**: Permite ejecutar bases de datos y herramientas en contenedores sin ensuciar el S.O. anfitrión ni tener conflictos de versiones.
  - **Entornos de Equipo Homogéneos**: Facilita que todo el equipo trabaje con la misma configuración exacta mediante un comando.
  - **Portabilidad a Producción (CI/CD)**: La misma imagen probada localmente o en integración continua se despliega en producción, eliminando el problema de *"en mi máquina funciona"*.
  - **Microservicios**: Aísla cada componente con sus dependencias específicas, facilitando el escalado y despliegue independiente.
  - **Seguridad (Sandboxing)**: Ejecuta código en entornos cerrados y seguros, muy útil para pruebas o ejecución de código generado por IA.
- **Conceptos Clave del Ecosistema**:
  - **Docker Hub**: Registro/repositorio oficial en la nube con miles de imágenes públicas listas para usar (bases de datos, lenguajes, etc.).
  - **Flujo de Ejecución (`docker run`)**:
    1. Busca la imagen en local.
    2. Si no existe, la descarga automáticamente de Docker Hub (usando la etiqueta `:latest` por defecto si no se indica versión).
    3. Crea y arranca el contenedor.
  - **Volúmenes**: Permiten el almacenamiento persistente de datos fuera del ciclo de vida del contenedor para evitar pérdidas de información.
  - **Builds**: Proceso estructurado en capas por cada instrucción del Dockerfile. Docker Desktop permite ver los tiempos, estadísticas y uso de caché.
- **Comandos Clave**:
  - **Verificación**:
    - `docker --version` - Comprueba la versión instalada de Docker.
    - `docker compose version` - Verifica la disponibilidad y versión de Docker Compose.
    - `docker info` - Muestra información detallada del sistema y del Docker Engine (CPU, RAM, contenedores totales).
  - **Gestión y Ejecución**:
    - `docker run <nombre-imagen>` - Crea y arranca un contenedor a partir de una imagen (ej. `docker run hello-world`).
    - `docker build -t <nombre-imagen> .` - Construye una imagen a partir de un Dockerfile en el directorio actual.
    - `docker run --rm <nombre-imagen>` - Ejecuta un contenedor y lo elimina automáticamente al finalizar.
    - `docker ps -a` - Muestra todos los contenedores (activos y detenidos).
