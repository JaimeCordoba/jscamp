## Notas Clave y Teoría

### 1. Uso de Imágenes Oficiales
- **Imágenes Oficiales**: Docker Hub ofrece miles de imágenes optimizadas y mantenidas oficialmente para múltiples tecnologías. Esto permite usarlas al instante sin ensuciar ni configurar dependencias en el sistema operativo local.
- **Descarga Automática de Imágenes**: Si la imagen indicada en el comando no está disponible a nivel local, Docker se encarga de buscarla en Docker Hub, descargarla, construir el contenedor y ejecutarlo de manera transparente.
- **Sesión Interactiva (`-it`)**:
  - `-i` (interactive) mantiene la entrada estándar (STDIN) abierta.
  - `-t` (tty) simula una terminal dentro del contenedor.
  - Permite interactuar con los REPL de lenguajes o con la shell de sistemas operativos (ej. bash en Ubuntu).
- **Parámetro `--rm`**: Elimina automáticamente el contenedor tras finalizar su proceso. Es una buena práctica para tareas puntuales y experimentación ya que evita dejar basura o residuos de contenedores detenidos en el host.
- **Ejecución Directa de Comandos**: Se puede enviar un comando directamente al contenedor para que lo ejecute y finalice inmediatamente (por ejemplo, obtener la versión de Node.js con `docker run --rm node:22 node --version`).

### 2. Creación de Contenedores Personalizados (Dockerfile)
- **Dockerfile**: Receta en modo texto que especifica cómo construir una imagen. Cada instrucción en el Dockerfile genera una nueva capa.
- **Imagen Base (`FROM`)**: Instrucción inicial obligatoria. Alpine Linux (`FROM alpine`) es sumamente popular debido a su tamaño reducido (pocos MBs) y su ligereza para entornos limpios y seguros.
- **Comando por Defecto (`CMD`)**: Especifica el comando de inicio que se ejecutará cuando el contenedor se ponga en marcha (ej. `CMD ["echo", "Hola Docker"]`). Solo el último `CMD` definido es efectivo; los anteriores se sobrescriben.
- **Directorio de Trabajo (`WORKDIR`)**: Define la ruta de trabajo dentro de la imagen (ej. `WORKDIR /app`). Evita utilizar la raíz del sistema operativo del contenedor y organiza mejor los archivos.
- **Optimización de Caché**:
  - Las capas se construyen secuencialmente y se guardan en caché.
  - **Práctica Recomendada**: Copiar primero solo los archivos de configuración de dependencias (`package.json` y `package-lock.json`), ejecutar la instalación (`RUN npm ci`) y, por último, copiar el código fuente (`COPY . .`). Así, si el código fuente cambia pero no las dependencias, Docker usará la caché para los pasos de instalación, reduciendo los tiempos de build drásticamente.
- **Seguridad (`USER`)**: Por defecto, los contenedores corren como `root`. Se recomienda configurar un usuario con menores privilegios (ej. `USER node`) para incrementar la seguridad.
- **Mapeo de Puertos**:
  - `EXPOSE <puerto>` sirve de documentación informativa sobre los puertos internos del contenedor.
  - Para poder acceder desde la máquina anfitriona (host), es mandatorio publicar los puertos al iniciar el contenedor utilizando la opción `-p` (ej. `docker run -p 5002:3000 nombre-imagen`, donde 5002 es el puerto de la máquina host y 3000 el del contenedor).

## Comandos Clave
- `docker run --rm -it python:3.12` - Ejecuta Python 3.12 de forma interactiva.
- `docker run --rm node:22 node --version` - Ejecuta un comando puntual y se elimina inmediatamente.
- `docker run --rm -it ubuntu bash` - Inicia un sistema Ubuntu completo para pruebas y navegación.
- `docker build -t hola-docker .` - Construye una imagen de Docker usando el `Dockerfile` de la carpeta actual y le asigna la etiqueta (`-t`) `hola-docker`.
- `docker run -p 5002:3000 hola-docker` - Ejecuta la imagen mapeando el puerto 5002 del host al puerto 3000 interno.
